    masuda/api/v1/masuda.proto¶

    masuda public API: what the CLI and any UI use. Served by masuda serve over Connect (gRPC and HTTP+JSON) on a Unix socket and, optionally, loopback TCP.

    Owned by masuda. Implementers do not change this file; proposals go to HANDOFF.md (see docs/design/contracts.md).

    Activity¶

    Activity is what the agent is doing right now, combined from host-observed API traffic (trustworthy) and guest hooks (informative).

    Field Type Label Description
    kind ActivityKind
    last_activity google.protobuf.Timestamp
    input_wait string From guest hooks: what Claude Code says it is waiting for.

    "permission", "idle", "question", "" | | detail | string | | |

    WorkspaceEvent¶

    One event on a Watch stream. Events whose workspace_id is empty concern the server as a whole (ServeNotice) and are delivered to every Watch, whatever id it asked for.

    Field Type Label Description
    seq uint64
    time google.protobuf.Timestamp
    workspace_id string
    status Workspace full status on every change
    engine EngineEvent one execution-record line
    guest_hook GuestHookEvent from the guest's Claude Code hooks
    http HttpActivity host-observed API traffic summary
    notice ServeNotice server-wide: disk usage, shutdown, ...

    ActivityKind¶

    Name Number Description
    ACTIVITY_KIND_UNSPECIFIED 0
    ACTIVITY_KIND_WORKING 1 API request in flight or recent tool use
    ACTIVITY_KIND_WAITING_INPUT 2 guest reports it is waiting for a human
    ACTIVITY_KIND_WAITING_GATE 3
    ACTIVITY_KIND_WAITING_QUESTION 4
    ACTIVITY_KIND_STALLED 5 alive but silent past the threshold
    ACTIVITY_KIND_DEAD 6 tmux session or claude process gone
    ACTIVITY_KIND_IDLE 7 nothing to do (done/stopped/blocked/suspended)

    WorkspaceState¶

    Name Number Description
    WORKSPACE_STATE_UNSPECIFIED 0
    WORKSPACE_STATE_STARTING 1
    WORKSPACE_STATE_RUNNING 2
    WORKSPACE_STATE_WAITING_GATE 3
    WORKSPACE_STATE_WAITING_QUESTION 4
    WORKSPACE_STATE_STOPPED 5
    WORKSPACE_STATE_DONE 6
    WORKSPACE_STATE_BLOCKED 7 A dead end: the engine recorded that the run cannot go on (e.g. a node used up its max with nowhere to go, or a triage halted it). Cannot be resumed. The sandbox is kept until Stop or Remove.
    WORKSPACE_STATE_SUSPENDED 8 Paused on a failure outside the engine's records: the sandbox failed to boot, or a host node could not run (an unapproved privileged command, the sandbox service failing an exec). Nothing was recorded for the node, so once the cause is fixed, Resume continues from the same node. The sandbox is kept (when it booted) so the guest can be inspected; Stop destroys it and makes the workspace STOPPED.

    WorkspaceService¶

    Method Name Request Type Response Type Description
    Run RunRequest Workspace Starts a workflow in a new workspace. Returns once the workspace exists and the sandbox is booting; follow with Watch.
    Resume ResumeRequest Workspace Resumes a STOPPED or SUSPENDED workspace from its records (new sandbox, re-clone; a SUSPENDED workspace's sandbox is destroyed first). A BLOCKED workspace cannot be resumed.
    Get GetWorkspaceRequest Workspace
    List ListWorkspacesRequest ListWorkspacesResponse
    Watch WatchRequest WorkspaceEvent stream Streams status changes and events for one workspace, or all when id is empty.
    Stop StopRequest Workspace Stops the sandbox but keeps records and staging; Resume continues. A BLOCKED workspace stays BLOCKED (its sandbox is destroyed).
    Remove RemoveRequest RemoveResponse Removes everything: sandbox, staging, records, exports kept aside.
    AttachInfo AttachInfoRequest AttachInfoResponse How to attach a terminal to the guest's tmux session.
