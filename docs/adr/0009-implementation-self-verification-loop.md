# ADR-0009: 実装フェーズはビルド/テストを自己修正ループで検証し、上限到達で停止する

## Status

Accepted (2026-07-25)

## Context

フェーズ5（実装）のサブエージェントはwrite/Edit/Bash権限を持つ。書いたコードがビルドやテストに失敗する状態のままフェーズ6（レビュー）に渡すのは、レビューの意味を薄れさせるため望ましくない。

一方で、実装エージェントがビルド/テストの失敗を無限に修正し続けようとすると、ループが終わらないリスクがある。

## Decision

実装サブエージェントは、自分で書いたコードをその場でビルド・テスト実行し、失敗したら自己修正して再実行する、というループを持つ。これは元々Bash権限を持っていることから自然に実現できる振る舞いであり、専用の別ロール（[[0004-checker-fixer-role-separation]]のような役割分離）は導入しない。ビルド可否・テスト結果は主観の余地がない客観的事実であり、レビューの指摘のような「独立した視点でのチェック」を必要としないため。

反復回数の上限を設け、上限に達してもビルド/テストがグリーンにならない場合は、フェーズ6に進めず停止する。停止後の扱いは[[0010-plan-deviation-reopens-plan-gate]]と同じゲート機構に合流させる。

## Alternatives Considered

- **ビルド/テスト結果を検証する専用のcheckerロールを分離する**: レビューの指摘とは異なり、ビルド/テストの成否は主観の入り込む余地のない客観的事実であるため、checker/fixerのような役割分離を持ち込む必要性が薄いと判断し不採用。

## Consequences

- 実装フェーズは自己完結した修正ループを持つが、上限を超えた失敗は自動では解決されず、必ず人間の判断に上がる
- 反復回数の上限は[[0011-iteration-budget-per-subagent-invocation]]の予算管理と同じ考え方（起動回数ベース）で設定する
