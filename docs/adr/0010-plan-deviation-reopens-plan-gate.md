# ADR-0010: プラン逸脱は自己申告+機械的バックストップの二段構えで検知し、G1を再オープンする

## Status

Accepted (2026-07-25)

- 一部改訂: [[0027-phase4-step-based-implement-review-commit-loop]] — バックストップの突き合わせ対象は「PLAN.md全体のファイル一覧」ではなく「そのステップの`files`」。review gate却下時のみ全ステップのunionを使う
- 一部改訂: [[0028-plan-predicted-byproducts-exempt-from-backstop]] — `expected_byproducts`にマッチするファイルは逸脱判定から除外される
- 一部改訂: [[0037-tdd-mode-red-green-refactor-subloop-in-phase4]] — TDDステップでは`since_ref`（前ステップのtag）基準で、作業ツリーとcommit済み差分を合算して突き合わせる
- 一部改訂: [[0059-remove-tdd-mode]] — 上の0037による改訂は失効した。`since_ref`はTDDモードとともに削除され、バックストップが見るのは作業ツリーだけに戻った

## Context

承認済みPLAN.mdと異なる実装をしたくなった場合、ユーザー自身がscope-discipline（宣言した範囲を超えない、プランと異なる判断は実装前に確認する）という原則を持っており、これを実装サブエージェントの振る舞いにもそのまま適用したい。

検知方法として、実装エージェント自身の自己申告に完全に依存する案が考えられるが、エージェントが逸脱に気づかない、あるいは指示に従わないケースまでは防げない。

## Decision

二段構えで検知する。

- **一次防御**: 実装エージェント自身が「計画から外れる必要がある」と気づいた時点で、勝手に進めず作業を止めてその旨をシグナルする、という行動原則を組み込む
- **二次防御（バックストップ）**: 自己申告に頼り切らず、フェーズ5完了後に実際の変更ファイル一覧をPLAN.mdの「変更するファイル一覧」と機械的に突き合わせる。計画外のファイルへの変更があれば、LLMを介さない決定的なチェックとして検知する。これはPLAN.mdが具体的な変更ファイル一覧を含むこと（[[0008-investigate-plan-agent-separation-with-redo]]で定めたPLAN.mdの構成）を前提にしている

逸脱が検知された場合、新しいゲート種別は作らず「G1（プラン承認ゲート）の再オープン」として扱う。[[0006-interactive-chat-plus-fast-path-gates]]と同じchat+approve/rejectの仕組みをそのまま使い、逸脱の理由を提示して人間が「そのまま進めていいか」「プランを見直すか」を判断する。

## Alternatives Considered

- **実装エージェントの自己申告のみに頼る**: エージェントが逸脱に気づかない、あるいは指示に従わないケースを防げないため、機械的なバックストップを併用することにした。
- **プラン逸脱専用の新しいゲート種別を作る**: G1と本質的に同じ「AIの設計判断が正しいかを人間が舵取りする」というゲートであり、別種のゲートを増やすと運用が複雑になるため、既存のG1を再オープンする形に統一した。

## Consequences

- PLAN.mdは「変更するファイル一覧」を具体的に書く必要があり、これが逸脱検知の判定材料になる（プランが曖昧だと機械的バックストップが機能しない）
- G1は一度きりのゲートではなく、フェーズ5の途中でも再オープンされうるものとして設計する必要がある
