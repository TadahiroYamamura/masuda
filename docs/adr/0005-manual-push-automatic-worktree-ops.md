# ADR-0005: git pushは常に手動、worktree操作は自動化してよいという権限境界

## Status

Accepted (2026-07-25)

- 一部改訂: [[0023-review-approve-fast-forward-not-local-merge]] — `review approve`のブランチ反映は`into`へのローカルmergeではなくfast-forward限定のPullになった。「pushは常に手動」という権限境界そのものは変わっていない

## Context

サンドボックス内のAIエージェントが自律的に実行してよい操作と、人間の承認を必要とする操作を区別する必要がある。当初は「破壊的かどうか・不可逆かどうか」を軸に検討していた（worktreeのマージ・削除も含めて全て承認ゲートを挟む案）。

しかし実際の懸念を確認したところ、本質は「自分が管理するAIエージェントが、自分以外の他人に迷惑をかけてしまう事態を防ぎたい」という点にあった。自分のマシンの中だけで完結する操作（ローカルの取り違え・やり直し）は影響範囲が自分に閉じており、コストの低いミスである。一方`git push`やPRコメントの投稿は、他人から見える・他人に影響しうる操作である。

## Decision

自動化してよいかどうかの判断軸を「破壊的かどうか」ではなく「**自分以外の誰かに影響するかどうか**」にする。

- worktreeのライフサイクル操作（作成・ローカルマージ・削除/後片付け）は、他人には一切見えないローカル操作のため、全て自動化してよい
- `git push`（およびPR作成・コメント投稿）は常にmasudaの自動化フローから切り離し、ユーザー自身が明示的に行う別操作とする。承認コマンド（`approve`）に紐付けない

この結果、`review approve`はworktreeブランチのローカルマージ・worktree削除まで自動で行ってよいが、pushは行わない。

## Alternatives Considered

- **破壊的・不可逆な操作は全てゲートで人間の承認を要求する（worktreeのローカルマージ・削除も含む）**: 実際の懸念（他人への影響）に照らすと過剰に保守的で、自分のマシンの中で完結する変更にまで不要な承認ステップを強いることになるため不採用。

## Consequences

- 「後片付けポリシー」（worktree/コンテナの後始末）が自動化で解決し、別途ゲートを設ける必要がなくなった
- 他人のPRをレビューする場合でも、fixerによる自動修正はworktree内で完結しpushしない限り外部に影響しないため、対象が自分の作業か他人のPRかで挙動を変える必要がなくなる（[[0004-checker-fixer-role-separation]]の自動修正ループがそのまま安全に使える）
- G1（プラン承認）・G2（レビュー承認）自体はこの原則とは別の理由（他人への影響ではなく、AIの設計判断が正しいかを人間が舵取りする必要があるため）で必須のゲートとして残る
