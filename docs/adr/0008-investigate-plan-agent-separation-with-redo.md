# ADR-0008: 調査・プラン作成は別エージェントとし、大きな調査不足はredoで差し戻す

## Status

Accepted (2026-07-25)

## Context

フェーズ1（調査）とフェーズ2（プラン作成）を、[[0002-workflow-orchestrator-with-subagent-delegation]]の原則通り別々のサブエージェント（新規コンテキスト）で実行することにした場合、「プラン作成フェーズで必要な情報を調査フェーズが全て集めきれる」という前提を置くのか、という疑問が生じる。

プランエージェントに調査エージェントと同じ広範なRead/Grep/LSPアクセスを持たせれば、軽微な確認漏れは自己解決できる。しかしこれだけに頼ると、調査の前提そのものが的外れだったというような大きなギャップがあった場合、プランエージェントが黙って独自に調査をやり直すことになり、フェーズ1を独立させた意味が薄れる。

一方で、プランエージェントが情報不足に気づくたびに正式なやり直しを要求すると、レビューフェーズの`check_node`が持つ「redo」の仕組み（チェックで問題が見つかったら、フィードバック付きで前段をやり直す）と同じ構造の問題であることに気づいた。

## Decision

調査とプラン作成は別々のサブエージェントとする。プランエージェントは調査エージェントと同じ広範なRead/Grep/LSPアクセスを持ち、軽微な不足は自分で追加調査して自己解決する。ただし前提から崩れるような大きな不足がある場合は、独自に調査をやり直すのではなく`{"status": "needs_more_investigation", "questions": [...]}`という構造化された信号を返し、オーケストレーターがフェーズ1へその質問を追加入力として差し戻す（MAX_RETRIESまで）。

INVESTIGATION.md自体には独立したゲートを設けず、そのままプラン作成に流し込む。

## Alternatives Considered

- **プランエージェントに調査アクセスを持たせず、INVESTIGATION.mdのみに厳密に依存させる**: 調査フェーズが完全であることを強制できるが、実際には多少の確認漏れは避けられず、そのたびに正式なredoを要求するのは過剰に硬直的なため不採用。
- **プランエージェントが独自に無制限に再調査してよいことにする**: フェーズ1の存在意義が薄れ、調査の質がフェーズごとに一貫しなくなるため不採用。

## Consequences

- 「軽微な自己解決」と「大きなギャップでの正式なredo」という2段階の仕組みが必要になり、プランエージェントの出力スキーマに`needs_more_investigation`のような状態を持たせる必要がある
- レビューフェーズのredoパターンと同じ形をフェーズ1-2にも適用することで、オーケストレーターの実装が一貫した設計になる
