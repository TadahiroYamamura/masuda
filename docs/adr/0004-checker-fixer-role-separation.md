# ADR-0004: 機械的な指摘の自動修正で、checkerとfixerの役割を分離する

## Status

Accepted (2026-07-25)

## Context

[[0003-mechanical-vs-complex-review-nodes]]で定義した「機械的チェック」の指摘（例: 命名が不自然）は、人間の判断を必要としない。そのため、G2（最終承認ゲート）で毎回人間に提示するのではなく、自動で修正して再検証するループを回したい。

一方、修正を行うサブエージェントとして、指摘を出したchecker自身に修正までさせると、「指摘した本人が自己採点で直す」ことになり、`review_node`/`check_node`を分離してきた本来の目的（独立した視点でのチェック）が崩れる。checkerがread-onlyでなくなることで決定性も失われる。

また、修正のたびにフェーズ5（実装）を丸ごと再起動するのは、命名修正のような小さな指摘に対して過剰に重い。

## Decision

checkerとfixerを別々のサブエージェントロールとして分離する。

```
mechanical checker（read-only）が指摘
  → fixer（指摘箇所のみ書き込み可、フェーズ5相当の大掛かりなセットアップは経由しない軽量なサブエージェント）が修正
  → 新規のchecker呼び出しで再検証
  → OKなら次へ / NGならMAX_RETRIESまでredo
  → それでも解決しなければ「未解決」としてG2に情報提供のみで上げる
```

fixerは指摘の内容・箇所だけを渡された、書き込み権限を持つ専用のサブエージェントとして都度起動する。checkerとは別コンテキストであり、フェーズ5全体のセットアップ（PLAN.md全体の読み込み等）は経由しない。

未解決のまま残った指摘は、`feat/github-actions-langgraph-nodes`の既存コードにある`unresolved_ids`の仕組みを流用し、G2に「未解決の意見対立」として情報提供のみで上げる。

## Alternatives Considered

- **checkerが自分で直接修正する**: 独立した視点でのチェックという目的が崩れ、決定性も失われるため不採用。
- **修正のたびにフェーズ5（実装）を丸ごと再起動する**: 指摘1件のために実装フェーズ全体のセットアップ・広いコンテキストを持つ実装サブエージェントを動かすのは過剰に重いため不採用。

## Consequences

- checker（read-only）とfixer（narrow write）という2つの異なる権限プロファイルを維持する必要がある
- 機械的な指摘はG2を経由せず自動的に解決できるようになり、人間が承認ゲートで対応する範囲は「複雑な指摘」と「自動修正が収束しなかった機械的な指摘」に絞られる
