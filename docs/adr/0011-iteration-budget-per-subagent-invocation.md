# ADR-0011: 予算管理の単位を「サブエージェント起動1回」に統一し、横断的チェックにはredoを持たせない

## Status

Accepted (2026-07-25)

## Context

[[0003-mechanical-vs-complex-review-nodes]]で、横断的チェックノードは1回の呼び出しが多ターンのエージェント探索になるため、機械的チェックが前提とする「1呼び出し=1単位」という予算管理（`MAX_RETRIES`・`ITERATION_BUDGET`）がそのままでは使えない、という課題を保留にしていた。

## Decision

`ITERATION_BUDGET`が数える単位を「1回のLLM API呼び出し」ではなく「**1回のサブエージェント起動**」に統一する。機械的チェックは元々1回の起動=1回のLLM呼び出しとほぼ同義なので挙動は変わらない。横断的チェックは、1回の起動の中で内部的に何ターンLSPを叩こうが「1単位」として数える。

サブエージェント単体の内部暴走は別レイヤーで止める。サブエージェント起動時にそれ自体の内部ターン数上限（LSP呼び出し回数の上限等）を持たせる。これはオーケストレーター側の`ITERATION_BUDGET`（起動回数の上限）とは独立した、エージェント単体の設定であり、「起動回数の上限」と「1起動内の内部探索の上限」の2層で無限ループを防ぐ。

さらに、横断的チェックには[[0004-checker-fixer-role-separation]]のような自動修正・redoのループを持たせない（複雑な指摘は常にG2で人間が判断する方針のため、[[0003-mechanical-vs-complex-review-nodes]]参照）。代わりに、探索するサブエージェント（explorer）とは別に独立した検証用サブエージェント（verifier）を1回だけ挟み、確認できた指摘だけをG2に上げ、確認できなければ破棄する1パス構成にする。これによりredo回数を管理する概念自体が不要になる。

## Alternatives Considered

- **横断的チェック専用の新しい予算管理概念（トークン数・実行時間等）を導入する**: 無限ループさえ防げればよいという方針（[[0001-self-loop-over-direct-api]]で従量課金ベースの予算管理を撤廃した判断と同じ考え方）に照らすと過剰に複雑なため不採用。既存の`ITERATION_BUDGET`の単位を再定義するだけで十分と判断した。
- **横断的チェックにもcheck_nodeのようなredoループを持たせる**: 複雑な指摘は自動修正しない方針（[[0003-mechanical-vs-complex-review-nodes]]）なので、redoで何をやり直すかが不明瞭になる。explorer→verifierの1パス構成の方がシンプルで一貫性があるため不採用。

## Consequences

- 予算管理の仕組みは機械的/横断的の両方で同じ`ITERATION_BUDGET`（起動回数ベース）を使い回せる
- サブエージェントの呼び出し設定に、オーケストレーターの予算とは別に「内部ターン数上限」というパラメータを新たに持たせる必要がある
- 横断的チェックの実装は「explorer 1回 → verifier 1回 → 確定 or 破棄」というシンプルな流れになり、機械的チェックのredoループとは異なる構造として実装する
