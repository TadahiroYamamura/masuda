# テスト

- テストケース名は日本語で、そのケースで何を確かめているかを文で書く（例: `UUIDが空のときはクエリを発行せず空のスライスを返す`）。既存テストが「正常系」のようなラベルだけ、または英語でも倣わない
- 判定ロジックのテストを書いたら、対象の分岐をわざと壊して（条件の反転・分岐の削除・定数のずらし）テストが落ちることを確かめる。落ちないテストは何も判定していない
- 新しいテストを足す前に、同じ前提（セットアップ・状態遷移）を既に辿っている既存テストを探し、その拡張で済まないか先に検討する。新規ファイルはセットアップの複製になるため最後の手段
- 入力と期待値を、実装の都合から独立させる
  - 入力: 曜日・enum・期間内の全日のように有限で小さい領域は、代表値を手で選ばず全件を回す。手で選ぶと、次元が交差するケース（日曜と重なった祝日など）を落とす
  - 期待値: 実装が使うライブラリの出力から作らず、仕様や手計算など別の源から用意する。同じ源から作ると、実装と源が同時に間違っていても気づけない
