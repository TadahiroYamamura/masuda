# 情報の置き場所

情報は、その情報が正しくあり続ける期間と同じ寿命の場所に置く。調査は `コード → git blame → コミット → PR / チケット / ADR` の順に辿られるため、コミットは他の情報源への中継点になる。

| 置き場所 | 寿命 | 残す情報 |
|---|---|---|
| コード | 現在 | 何をどうしているか |
| テスト | 現在 | 期待される振る舞いの具体例 |
| コメント | そのコードが存在する間 | このコードがこの形である理由（制約・選ばなかった代替案・直感に反する点） |
| コミットメッセージ | その時点で固定 | なぜこの変更をこのタイミングで入れたか |
| PR | その時点で固定 | レビューのための文脈、動作確認の内容、議論の経緯 |
| チケット | その時点で固定 | 解決すべき問題、業務上の背景、要望の出どころ |
| ADR | 置き換えられるまで | モジュールをまたぐ、戻しにくい決定（制約・代替案・結果） |

- コードが存在する限り正しい理由 → コメント
- 変更した時点の事情（きっかけ、移行途中、削除・置き換えの理由） → コミットメッセージ
- 既知の懸念・今後の課題 → チケットまたは TODO コメント（コミットに書くと blame しない限り見つからない）
